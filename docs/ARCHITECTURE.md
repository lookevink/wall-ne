# Authoritative boundaries

`engine.py`, `treatment.py`, `care.py` and `manipulation.py` own physical state. Commands return stable receipts; world checkpoints serialize receipts, inventories, ledgers and pending actions. `observations()` is a filtered policy projection; `snapshot()` is privileged operator/rendering state.

`Runtime` is a session writer with an independent fencing identity. It commits accepted commands before stepping physics. Every physical step is sampled; progress, telemetry, receipts and the matching checkpoint share a database sequence boundary. Artifacts upload first under content hashes. A failed commit retains the same batch ID and blocks new work. The server never treats a local cache as a persistence substitute.

`TreatmentRuntime` coordinates request-specific browser captures and scans. Python decodes actual bounded PNG bytes, validates frame/revision identity, and waits for durable artifacts before using evidence. The renderer computes first-surface depth from visible geometry; Python validates rays and independently computes tool contact. No browser API accepts arbitrary robot telemetry or a replacement world state.

`arm.py` provides analytic six-joint FK/IK and sampled swept-link collision checks. `manipulation.py` adds measured grip/load, side-slip, root resistance, extraction and release-in-bin rules. These are explicit kinematic simulation rules, not a rigid-body or hardware model.

`orchard_manipulation.py` specializes those mechanics for W1 in the main orchard: one durable state owns apron navigation, the world-coordinate plant inventory, arm motion, collection and return. The main runtime selects this mission by default; fleet watering is separately selectable. `orchard-arm.js` attaches the sensor-visible manipulator and plants to the existing `FleetScene`. Camera RGB and LiDAR use that scene, with shader displacement disabled and stable fruit visibility. Saved arena identity prevents restoring a laboratory checkpoint into an orchard runtime. New live arm scripts and evaluation campaigns target `/`, while calibration fixtures remain in the laboratory.

`inference.py` sends one required tool call per request outside the simulation lock. Only the validated command seam mutates the world. `review.py` filters evidence and applies the fixed promotion metric; `evaluation.py` runs finite paired sessions under a frozen manifest. SQL additionally protects immutable prompt contents and activation requirements.

## Coordinated full care

The main orchard's **All workers · full care** mission uses `FleetCareWorld` and `FleetCareRuntime`, with a choice of ten trees or all 169. Ultra Fast control schedules exclusive tree/worker assignments for W1–W5; live models make the visual treatment decisions. R1 retains its recovery role. Each assignment is a linked durable worker session, with its own current image, measured state, provider accounting and independent completion checks. The parent cannot complete until every requested tree passes every care check, all five workers participated, and the fleet is at its docks above reserve.

`OrchardCare` combines visual inspection, metered irrigation and fertilizer, image-ray pest contact, and articulated wrist-camera extraction. The fixed service camera is offset 0.75 m from the arm; extraction uses the calibrated wrist camera. Public tree/basin coordinates are available for irrigation; hidden weed and insect coordinates stay out of model observations. Delivery uses the measured remaining target, stock limits and a root-basin aim guard. Pest treatment is a bounded vacuum contact model, not articulated insect grasping. Dock service takes simulated time, records replenishment and unloads collected weeds. Every tree retains its inspection and stage-evidence references.

Only one rover may navigate through the shared apron at a time; workers treat separate trees concurrently. The browser renders all worker arms in the same orchard. A LiDAR request reuses the exact captured scene geometry, including other workers, for that frame. Sensor submissions require the correct worker, child session, frame and revision. Parent stop, storage and terminal barriers pause child execution. Recoverable failures keep the unfinished task active: camera/depth timeouts issue fresh captures, provider outages back off and retry, and policy stops or repeated rejected actions request collision-checked camera recovery. Recovery preserves measured care, resources, contact checks and failure evidence. A terminated recoverable attempt continues in a linked child session with the same physical state and exclusive task ownership; historical attempts remain evidence and never count as completed trees. Operator stops and physical integrity guards remain authoritative. Restore reconciles workers that completed before their parent checkpoint caught up.

Fleet limits are 90 wall minutes and $10 reported cost, shared across workers and recovery attempts; workers have no smaller per-attempt budget or frame/decision-count cutoff. Unknown provider costs remain unknown. New full-care sessions default to a pinned Gateway fallback after the first provider/protocol failure, with Gemini 4 Argon (`google/gemini-4-argon`, Gateway catalog checked 2026-10-17) for treatment; explicit disabled fallback remains respected. The fallback uses low reasoning effort, a 2,048-token output budget and a 30-second request timeout. Existing sessions keep their pins; an explicit `refresh_fallback: true` on `/api/continue-care` updates parent and unfinished worker fallback policies in new linked sessions, preserving prior inference accounting and care evidence. Physical misses trigger observation/pose recovery rather than a provider switch. `python3 -m scripts.fleet_care_mission --start` runs the ten-tree mission with the main orchard browser open; omit `--start` to monitor and export the current mission.

Controller updates can use `POST /api/continue-care` to create a paused, explicitly linked new session from a stopped saved fleet. This preserves physical state and completed evidence, resource/cost/time counters, and each worker's provider/model pins. It requires committed storage and settled inference; damaged inventory or protected-organism damage rejects continuation. All worker snapshots are validated before creation, failed child creation is closed, and source session outcomes remain unchanged. Continuations require fresh sensor frames and do not count as a single frozen implementation run.

Full-care arm alignment additionally requires `project_ground` evidence: a selected current-image ray intersected with the public y=0.08 m plane. The observation keeps that surface point separate from the y=0.13 m gripper-center convention. The tool does not read plant positions or snap to a specimen, and a projection or visual alignment claim cannot establish physical contact. Misses clear the projection and require a wide-view rescan.

## Season calendar

`almanac.py` owns the orchard calendar: day number, sun path (36.7° N, from 2 June), daily weather and per-tree morning ecology for the ten care trees. `Season.next_day(outcomes)` turns one day's measured end state (moisture, applied fertilizer, weed extraction, remaining pests) and that night's weather into the next morning. Those conditions become the care tasks: weed specimen and growth stage, pest count, soil moisture and fertilizer prescription. Weed growth changes rendered size and leaf count inside the validated specimen range. Grasp physics are unchanged. Each day's world saves `season` with its checkpoint, and `metadata.configuration.season_day` lets a restarted server continue the latest season.

`DayClock` is operator-facing time. It advances only while the day's mission runs, freezes while it is paused, and sweeps to nightfall after the mission settles. It never feeds mission physics or model observations. The server's `begin_day` replaces the fleet runtime and starts it immediately. Optional auto-advance runs from a server thread and stops after two consecutive blocked days.

`orchard-epoch.js` renders time of day only for operator views: sun and moon light, sky, mist, rover and dock lamps, and wet-soil decals sized by live moisture. Decision captures and decision-camera tiles run inside `Atmosphere.calibrated()`, which restores the validated lights, fog and unlit material colors. Lamps and decals stay on layer 1, so RGB decisions and LiDAR exclude them. Timelapse frames are saved locally under `.runtime/timelapse`.

`film.py` generates season films. `FilmDay` runs five single-tree `OrchardCare` worlds with one apron-lane reservation, and `ScriptedWorker` drives each world from simulator truth through the ordinary command seam. Synthetic frame acknowledgements and ground-plane LiDAR returns satisfy the sensor protocol without pixels. A dry run measures each day's work, so every day fills the same frames. Frames carry the fleet-care snapshot shape, and `/film.html` renders them through the same `FleetScene` with `Atmosphere.set()` (no easing).

The opt-in `ultra_fast` full-care controller is documented in [ULTRA_FAST.md](ULTRA_FAST.md). It keeps live image identification and independent physical checks, automates routine care, and uses a durable local SQLite outbox for evidence. Local persistence precedes control progress; Supabase artifact/checkpoint replication is asynchronous. Operator state distinguishes locally queued and cloud-committed sequences. Startup resumes delivery, and cloud-based restoration/continuation waits for preexisting evidence to sync. Standard mode retains synchronous Supabase barriers.

Recovery from a legacy carried-arm/trunk overlap uses a bounded chassis retreat with fixed, open, empty jaws. The planner checks chassis clearance and per-trunk arm penetration every 2 cm: existing contact cannot deepen, new contact is forbidden, and the endpoint must be clear. Retreats share the fleet navigation reservation, consume motion time and battery, and trigger fresh RGB/depth. Parking checks the carried arm as well as the chassis; navigation checks arm clearance before each physical step.

For an explicitly requested local server update, `python3 -m simulator.server --continue-running SESSION` binds the server port, reads the latest integrity-checked checkpoint from the locally owned durable outbox (or cloud after it has drained), and creates a linked continuation that starts before serving HTTP. It refuses unresolved inference accounting. Ordinary HTTP continuation still requires stopped source sessions. The old outbox keeps replicating unchanged. No operator pause/start cycle is needed for this startup handover.

A finished care attempt with a failed preservation check records `task_exception` and `tree_requires_review`, stows, returns to its dock and services before ending as `failed`. The fleet marks that assignment `requires_review` and releases the worker for unassigned trees. The damaged tree never counts as a verified success. Once all assignments are completed or require review, the fleet reports a failed outcome with incidents instead of claiming clean completion. Startup continuations retain organism damage so this return/service path can finish after an update; ordinary recovery never erases that evidence.
